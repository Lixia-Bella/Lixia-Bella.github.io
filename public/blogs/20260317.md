# 阳光小站 HTML5 语义化标签与页面结构设计

> 作者：Bella ｜ 日期：2026-03-17

语义化不是“把 `div` 换成更高级的标签”这么简单，它的核心价值在于让浏览器、搜索引擎、辅助技术和团队成员都能更准确地理解页面结构。本文结合个人站点的页面组织方式，总结 HTML5 语义化标签的使用场景与常见误区。

## 一、为什么要做语义化

在页面规模较小时，几层 `div` 看起来也能工作；但当页面包含导航、内容区、侧边区域、卡片列表、页脚等多个模块后，纯 `div` 结构会让可读性迅速下降。语义化标签的意义主要体现在三个方面：

- **代码可读性更高**：看到标签名就能知道该区域的职责。
- **SEO 更友好**：搜索引擎更容易理解内容主次。
- **无障碍体验更好**：屏幕阅读器能更准确地识别导航、主内容、标题层级等信息。

例如，以下结构比单纯的 `div` 更清晰：

```html
<header>...</header>
<nav>...</nav>
<main>
  <article>...</article>
  <aside>...</aside>
</main>
<footer>...</footer>
```

## 二、常用语义化标签的职责

### `header`

`header` 通常表示页面或区块的头部信息，可以放置站点标题、Logo、简介、操作按钮等。需要注意的是，`header` 不一定只出现一次，一个 `article` 内部也可以有自己的 `header`。

### `nav`

`nav` 表示主要导航区域，适合包裹站点主导航、目录导航、分页导航等。并不是所有链接集合都要写成 `nav`，例如页脚里零散的版权链接就不一定属于主要导航。

### `main`

`main` 表示页面的主要内容区域，一个页面通常只应有一个 `main`。它应当排除掉导航、页脚、侧边固定工具栏等重复性区域，让读屏工具能快速定位核心内容。

### `section`

`section` 用于表达“有主题的内容分组”，通常应配合标题使用。如果一块内容没有明确标题，仅仅是为了布局包一层，往往更适合用 `div`。

### `article`

`article` 适合表示可以独立分发、独立阅读的内容单元，例如博客文章、新闻卡片、评论项、帖子等。博客列表中的每篇文章卡片就很适合使用 `article`。

### `aside`

`aside` 表示与主体内容相关但非核心的信息，例如作者资料、推荐阅读、广告位、目录说明等。

### `footer`

`footer` 一般用于区块尾部，放置版权信息、作者信息、补充链接等。与 `header` 一样，它既可以是页面页脚，也可以是某篇文章内部的尾部信息。

## 三、页面结构设计思路

在搭建页面时，我通常先不考虑颜色和动画，而是先写“骨架”。一个典型博客首页的结构可以拆为：

1. 顶部站点信息与导航
2. 文章列表主区域
3. 额外兴趣内容与引导模块
4. 页脚版权信息

如果先把结构写清楚，后续 CSS 和 React 组件拆分会自然很多。例如首页可以先组织成：

```html
<body>
  <header>站点标题与入口信息</header>
  <nav>主导航</nav>
  <main>
    <section>文章列表</section>
    <section>爱好展示</section>
    <section>功能入口</section>
  </main>
  <footer>版权信息</footer>
</body>
```

这样的结构天然适合后续抽成 `Layout`、`Navbar`、`HomePage` 等组件。

## 四、标题层级要连续

语义化不仅是标签选择，还包括标题体系的设计。最常见的问题是视觉上想让某段标题更大，就直接随意使用 `h1`、`h4`。正确做法应该是按内容层级组织：

- 页面主标题使用 `h1`
- 页面内主要模块使用 `h2`
- 模块内子主题使用 `h3`
- 更细分内容再使用 `h4`

标题层级连续可以帮助搜索引擎和屏幕阅读器理解内容结构，也方便 CSS 用统一规则控制字号，而不是让标题标签承担纯视觉作用。

## 五、什么时候不要滥用语义标签

语义化不是“标签越高级越好”。以下情况更适合继续使用 `div`：

- 只是为了做布局包裹
- 只是为了添加样式钩子
- 内容没有明确主题或标题
- 组件内部只是若干装饰性结构

例如卡片里的按钮组、图标容器、辅助装饰层，通常没有独立语义，使用 `div` 更稳妥。

## 六、一个简单的实践原则

我给自己总结了一个判断方法：

> 如果拿掉样式后，这个区域仍然能被清楚地描述为“导航”“文章”“侧边补充信息”“页脚”，就优先考虑语义化标签；如果它只是一个视觉容器，就继续用 `div`。

## 七、总结

HTML5 语义化的重点不在于“记住多少标签”，而在于建立清晰的信息层级。只要先把页面结构想明白，再选择最合适的标签，后续无论是写 CSS、做 React 组件拆分，还是优化 SEO 和无障碍体验，都会轻松很多。
