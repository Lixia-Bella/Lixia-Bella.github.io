# 阳光小站 Flexbox 与 Grid 布局完全指南

> 作者：Bella ｜ 日期：2026-03-18

Flexbox 和 Grid 是现代 CSS 布局最重要的两套工具。很多初学者会纠结“到底该学哪个”，其实更合理的问题是：什么场景下用 Flexbox 更自然，什么场景下 Grid 更高效。本文从思维模型、核心属性和典型案例三个维度做一次系统梳理。

## 一、先理解两者的布局思维

### Flexbox：一维布局

Flexbox 更擅长处理**一行**或**一列**上的排列问题。它关注的是主轴与交叉轴上的对齐关系，非常适合：

- 导航栏链接横向排列
- 按钮组间距控制
- 卡片内部图标和文本的对齐
- 表单项在单行中的布局

一句话概括：**当你主要关心一个方向上的分配与对齐时，优先考虑 Flexbox。**

### Grid：二维布局

Grid 更擅长处理行和列同时存在的场景，也就是**二维布局**。它很适合：

- 卡片列表的多列网格
- 后台管理页面的整体版式
- 相册、看板、数据面板
- 需要明确控制“第几行第几列”的区域

一句话概括：**当你需要同时设计行和列的结构时，优先考虑 Grid。**

## 二、Flexbox 常用属性速查

一个典型的 Flex 容器通常从这几项开始：

```css
.container {
  display: flex;
  justify-content: space-between;
  align-items: center;
  gap: 16px;
}
```

### `justify-content`

控制**主轴方向**上的排列方式，常见值有：

- `flex-start`
- `center`
- `space-between`
- `space-around`
- `space-evenly`

例如导航栏两端对齐时，经常会用到 `space-between`。

### `align-items`

控制**交叉轴方向**上的对齐方式，最常用的是：

- `stretch`
- `center`
- `flex-start`
- `flex-end`

图标和文字需要垂直居中时，`align-items: center;` 几乎是默认选择。

### `flex-wrap`

决定子元素是否允许换行：

```css
.tags {
  display: flex;
  flex-wrap: wrap;
  gap: 8px;
}
```

标签列表、按钮云、响应式卡片工具条都非常适合这种写法。

### `flex: 1`

它是 `flex-grow`、`flex-shrink`、`flex-basis` 的简写，常用于让某个元素自动占满剩余空间。例如搜索框区域自适应扩展：

```css
.search-input {
  flex: 1;
}
```

## 三、Grid 常用属性速查

Grid 最核心的是先定义“几列几行”：

```css
.grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 20px;
}
```

### `grid-template-columns`

用于定义列结构，常见写法有：

- `repeat(3, 1fr)`：三列等宽
- `240px 1fr`：左侧固定、右侧自适应
- `repeat(auto-fit, minmax(240px, 1fr))`：响应式自动换列

在卡片列表中，`minmax()` 特别实用：

```css
.card-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));
  gap: 24px;
}
```

### `gap`

`gap` 不仅 Grid 能用，Flex 现在也普遍支持。它可以统一控制行列间距，写起来比手动给子元素加 `margin` 更干净。

### 区域命名

Grid 还能给页面区域命名，做整体版式很直观：

```css
.layout {
  display: grid;
  grid-template-areas:
    "header header"
    "sidebar main"
    "footer footer";
}
```

这种方式特别适合页面骨架布局。

## 四、Flexbox 与 Grid 的选择建议

### 场景一：导航栏

导航栏通常是一维排列，里面会包含 Logo、链接、按钮等内容，这类结构更适合 Flexbox。

### 场景二：文章卡片列表

如果是“若干张卡片组成多列列表”，整体容器用 Grid 更自然；而卡片内部的标题、标签、按钮区域，继续用 Flexbox 处理局部对齐。

### 场景三：页面整体骨架

例如“左侧菜单 + 右侧内容 + 顶部头部 + 底部页脚”，Grid 会比 Flexbox 更容易表达整体区域关系。

## 五、一个很实用的组合思路

真实项目里很少只用一种布局工具，更常见的是：

- **页面大结构用 Grid**
- **局部组件内部用 Flexbox**

例如：

```css
.page {
  display: grid;
  grid-template-columns: 260px 1fr;
}

.card-header {
  display: flex;
  justify-content: space-between;
  align-items: center;
}
```

这种组合方式既清晰又高效。

## 六、响应式中的常见做法

### Flexbox 响应式

当一行放不下时，可以直接换行：

```css
.toolbar {
  display: flex;
  flex-wrap: wrap;
  gap: 12px;
}
```

### Grid 响应式

通过 `auto-fit` + `minmax()` 实现自动列数变化：

```css
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
  gap: 20px;
}
```

这样在桌面端可以显示多列，在移动端会自然收敛为单列或双列。

## 七、常见误区

### 用 Flexbox 强行做复杂二维布局

如果你开始频繁写嵌套 Flex 容器、反复计算宽度、还要处理多行对齐，通常说明应该改用 Grid。

### 用 Grid 处理非常简单的一行对齐

例如按钮横排、图标加文字这些小场景，用 Grid 往往显得过重，不如 Flexbox 简单直接。

### 忽略 `gap`

很多人还在靠子元素 `margin` 控制间距。现在无论是 Flex 还是 Grid，优先使用 `gap` 会让布局更稳定，尤其在换行时更明显。

## 八、总结

Flexbox 和 Grid 不是竞争关系，而是互补关系：

- **一维问题用 Flexbox**
- **二维问题用 Grid**
- **整体与局部组合使用**

当你不再纠结“二选一”，而是先判断布局问题的维度，再选工具，CSS 布局就会轻松很多。
